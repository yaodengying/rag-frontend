# 2026-10-15

## 「流式问答是否重试」前端落地（rag-frontend）

需求：后端（rag-backend）已把 `enable_retry` 做成三态 + `/chat/options` 能力发现 + `done` 回填
收尾事实，这一步把它接到**真实前端**，让用户能自己选。

### 结果
- **请求层**（`src/api/modules/chat.ts`）
  - `ChatRequest.enableRetry?: boolean | null`，注释里写死三态语义；
    `streamChat` 只在 `!== undefined` 时发 `enable_retry`（显式 `false` 也必须发出去）。
  - 新增 `GET /chat/options` → `fetchChatOptions()` + `normalizeChatOptions()`（snake_case 归一），
    `skipErrorToast` 默认 true（开关初始化失败不该盖住页面其它提示）。
  - 事件模型加 `{type:'retry', attempt, maxAttempts, reason?}` 与 `{type:'done', info?}`；
    `ChatStreamResult` 带 `done?: ChatDoneInfo`。
  - `decodeChatChunk` 原来把 `event: done` 直接丢成 `{type:'done'}`，**事件体整个被扔掉**——
    这是本次最关键的一处修改，否则 `can_retry` 永远拿不到且无报错。
- **store**（`src/store/chat.ts`）：`ChatMessage` 增 `question / refused / retried / attempts /
  canRetry / query / retrying`；新增 `applyTurnFacts / resetAssistantMessage / setRetrying /
  dismissRetry`；`startAssistantMessage(question?)` 把问题存在**消息上**（比回头找"上一条用户
  消息"稳，那条关系会被插入、重发、切会话打乱）。
- **hook**（`src/hooks/useChatStream.ts`）：抽出 `runTurn(question, assistantId, history,
  enableRetry)`，「首次提问」与「当场再试」共用（写两份必然漂移）。新增 `retry(messageId)`：
  复用同一条助手消息、强制 `enableRetry=true`、history **丢掉紧邻的用户消息**（否则同一问送两遍）。
  收尾事实**先于** `finalizeMessage` 写入——`finalizeMessage` 只接受 streaming→终态这一次转换，
  顺序反了提示永远不出现。
- **页面**（`src/pages/Chat/index.tsx` + `chat.css`）
  - 顶栏预设开关「检索不到时改写重试」：初值 = `GET /chat/options` 的 `stream_retry_default`；
    Tooltip 说明上限/代价/与非流式的关系。**读不到能力清单时置灰、不发字段，绝不猜**。
  - 气泡内「再找一次 / 不用了」提示（仅 `can_retry` 时出现）；改写期间把"正在思考"换成
    「首轮没找到，正在改写查询后重新检索...」；`retried` 时显示「已用改写后的查询重新检索：〈查询〉」；
    拒答气泡用琥珀色样式与正常回答区分（`chat-bubble--refused`）。
  - 历史会话灌进来的消息一律 `canRetry:false`（重发要带当时的上下文，历史里只有消息本身）。
