## 本轮踩坑记录

- **shell 里有 `http_proxy=http://127.0.0.1:56648`**，curl 访问 localhost 会走代理并返回 502。本地自测必须加 `--noproxy '*'`。

### 关键设计
- 响应拦截器与 SSE 共用 `handleUnauthorized`，两套链路的 401 行为一致。
- **库的三个坑已在 sse.ts 里抹平**：① 库只校验 content-type，不校验 HTTP 状态，401/500 会被当正常流 → 在 `onopen` 里自行校验；② 库出错默认静默重连并重放请求，流式对话会导致答案重复 → `onerror` 里抛错终止，重连仅在「尚未收到任何内容」时允许；③ 服务端不断连时连接会假死 → 加空闲超时（默认 60s，每次收到消息重置）。
- 收到 `[DONE]` 通过 `controls.stop()` 抛内部 `StreamStopSignal` 结束流，让库走 `dispose()` 主动断开，**不必等服务端断连**（实测 5ms 结束）。
- `streamChat` 的错误分层：出错 reject（ApiError）；被 cancel 时 **resolve** 并带 `aborted: true` + 已生成的部分内容，对聊天 UI 更友好。
- 默认解码器兼容：`[DONE]`/`event: done`、`event: error`、业务包裹体 `{code,message,data}`、`content|delta|text|answer|token`、OpenAI `choices[0].delta.content`、`references|sources|docs|citations`、非 JSON 纯文本。后端不同可传 `options.decode` 覆盖。

## 修复：后端未启动时登录暴露原始代理报错（proxy target unreachable）

用户报 `proxy target unreachable: connect ECONNREFUSED 127.0.0.1:8000`。根因：**登录链路没有 mock 兜底**，后端不在时 `/api/auth/login` 返回 599，响应体里的原始报错被 `pickBackendMessage` 提取后直接显示在登录表单上。修复：

- `PROXY_UNREACHABLE_STATUS(599)` 常量移到 `src/api/config.ts`（error.ts 与 mock.ts 共用，避免循环依赖）。
- vite 代理 599 响应体改为 `{code, message: '后端服务未启动或不可达', proxyError, target}`——`message` 会被当后端文案提取，原始报错放 `proxyError`（不在提取列表）仅供排查。
- `error.ts` 对 status 599 强制使用友好文案 `BACKEND_UNREACHABLE_MESSAGE`，并新增 `isCanceled()` 判定；`mock.ts` 的 `isNetworkError` 改用共享常量。
- `auth.ts` 的 `login`/`fetchProfile` 接入 `withMock`：后端不可达时假登录（任意账号，token `mock-token-<username>`）/ 沿用本地用户，`fetchProfile` 兜底取 store 里的 user 避免刷新被踢回登录页。登录页加「开发模式：后端未启动时可用任意账号登录」提示。
- 顺带修复：页面级 catch 会把「请求已取消」（StrictMode 双挂载中断首批请求）当错误弹 toast——`KnowledgeBase`/`Documents`/`Login` 的 catch 增加 `isCanceled` 跳过。
- 验证（Chrome headless + CDP，后端 8000 确认无监听）：mock 开 → 任意账号登录成功落 `/knowledge-base`，无原始报错、无多余 toast；mock 关（`VITE_USE_MOCK=false`）→ 登录失败但提示为「后端服务未启动或不可达」。`tsc -b`/`oxlint`/`build` 全过。
